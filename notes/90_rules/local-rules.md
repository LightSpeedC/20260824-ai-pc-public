## 1. 伏せる金額

このリポジトリは公開する前提です。次の金額は**ドキュメントにも Claude Code の応答にも書きません**。

| 対象 | 扱い |
|---|---|
| 見積金額 | ❌ **伏せる** 個別に受領した見積の提示額 |
| 見積の値引き額 | ❌ **伏せる** 案件値引きの額、および値引き前後の差額。**差額から見積金額が逆算できます** |
| 学割金額 | ❌ **伏せる** 学生・教職員向けストアの価格、割引額、割引率 |

> [!NOTE]
> <strong>会話は JSONL に残ります。</strong>ファイルから消しても、応答に書けばログに残ります。ファイルと応答の両方が対象です。

## 2. 書いてよい金額

公開情報として誰でも参照できる金額は、そのまま書きます。

| 対象 | 扱い |
|---|---|
| メーカーの掲載価格 | ✅ **書く** キャンペーンページ・直販ページの価格 |
| 定価 | ✅ **書く** 標準販売価格・希望小売価格 |
| 公式ストアの通常価格 | ✅ **書く** 構成を選択して取得した価格 |

比較表の基準価格・差額は、伏せた金額ではなく**公開情報の価格を基準に組み直します**。

## 3. 価格の再確認

GB10 搭載機の通販価格は数日で往復します。実例として、DGX Spark が 4 日で 18 万円下落し、その 2 日後に 73 万円上昇しました。**最安の機種そのものが入れ替わります。**

| 項目 | 決めごと |
|---|---|
| 周期 | **奇数日の 6:00**。cron の式は `0 6 1-31/2 * *`、prompt は「ローカルルール3章に従って価格を再確認する」 |
| 確認後の更新 | 資料の更新日と、1 章の「価格はすべて yyyy-mm-dd に確認しました」の日付を揃える |
| 動いていないとき | 更新日も変えない（体裁だけの変更に当たる） |
| 止まっていたとき | セッションを開き直したときなどに、前回の実行から 奇数日 6:00 の予定を1回以上過ぎていたら、cron を作り直したうえで、待たずにその場で1回実行する |

## 4. URL へのアクセス手段

このプロジェクトでベンチマーク・製品情報など外部 URL の参照が必要なときの手段の優先順位です。共通ルール「共有環境の使い方」の「URLへのアクセス手段の選択」を上書きします。

<strong>共通ルールとの違いは 1 点です。</strong>WebSearch・WebFetch で取得できなかったとき、共通ルールは切り替える前に利用者へ確認を取りますが、このプロジェクトでは確認を取らずに Computer Use へ切り替えます。理由は、価格・ベンチマークの取得では JS 描画で本文が取れないページが多く、利用者がこの切り替えを事前に承認しているためです。

| 優先順位 | 手段 |
|---|---|
| 1 | WebSearch ・ WebFetch |
| 2 | だめなら Computer Use による Chrome 操作 |

この順で試す。WebSearch・WebFetch で目的の内容が取得できなかったときだけ Computer Use に切り替える。

<strong>Computer Use で読めなかったページ（ボット確認・ログイン要求など）は、タブを閉じずに残し、URL と読めなかった理由を利用者に伝える。</strong>利用者がそのタブで確認を済ませたら、読み直してから閉じる。理由: 利用者が同じページを開き直さずに済み、こちらも同じタブを読める。

## 5. commit・push

共通ルールの「修正は1点ずつ、確認を重視」と「重大な操作の確認方法」を上書きし、commit・push は指示を待たずに行う。理由は、価格を1日2回確認するので、更新のたびに指示を待つと公開ページが遅れるため。

| 項目 | 決めごと |
|---|---|
| 単位 | 1つの目的が片付いたところ（価格の再確認1回分、資料の修正1件など） |
| 指示を待つもの | 履歴の書き換え（amend・reset・force push） |
